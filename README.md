# EasyQR

[![build](https://github.com/Northodieart/EasyQR/actions/workflows/build.yml/badge.svg)](https://github.com/Northodieart/EasyQR/actions/workflows/build.yml)

EasyQR 是一个面向 **Windows 11 x64** 的轻量屏幕二维码 / 条码识别工具。启动后点击「全屏识别」或「框选识别」：识别出的网页直接交给系统默认浏览器；没有网页的内容会进入识别结果面板，可查看并复制。也可以关闭主界面常驻托盘，用全局快捷键随时唤起扫描，并在设置中从 GitHub 检查安装更新。

界面为原生 Win32 + Direct2D / DirectWrite + DWM 实现的 Fluent 风格，主窗口、抓屏浮层和结果面板统一使用 Acrylic 玻璃，并提供 **无模糊 / 静态模糊 / 动态模糊** 三档可选；不依赖 WinUI 3 / .NET 运行时，便携版只是一个约 2.3 MB 的 EXE。界面事件驱动、无常驻动画，隐藏到托盘或最小化时会释放图形资源。

## 功能

### 紧凑主界面与原生外观

- 主窗口只有 **全屏识别**、**框选识别** 两个大图标入口，默认尺寸约 400 × 240 DIP，尽量不遮挡屏幕。
- 自定义无边框标题栏：应用图标、设置、最小化、关闭集中在一行，不显示原生标题栏，也没有最大化按钮。
- 除识别卡片、设置/标题栏按钮等可交互控件外，窗口任意空白区域都可以按住拖动。
- 主窗口与抓屏浮层使用同一套 **Acrylic** 玻璃，并在设置中提供四档：**无模糊**（纯色）、**静态模糊**（采样当前屏幕后模糊，拖动时重新采样）、**动态模糊**（约 50 fps 在后台线程实时采样整块桌面并模糊，背景视频和拖动过程中都持续跟随）、**实时透明**（不采样、不模糊，窗口表面带真正的逐像素 Alpha，桌面直接透出来，和 Windows 终端的透明度同一原理，因此绝对零延迟；需要 Windows 11 24H2 及以上，不满足时自动按无模糊显示）。浅色 / 深色 / 跟随系统主题会同步应用到背景和控件。
- 动态模糊在 `StretchBlt` 内部就把桌面缩小到约 1/12 再模糊，一次采样只有一个很小的缓冲区，单帧开销在毫秒级，并且拖动窗口时不会停下来等采样；无模糊与静态模糊不做任何持续采样，静态模糊只在显示、恢复、扫描结束和开始拖动时各采样一次。
- 如果屏幕捕获不可用，会自动回退为纯色背景，标题栏和布局保持一致。
- 设置页从标题栏下方以约 200 ms 的 Windows 风格缓出动画向下展开到 400 × 560 DIP，返回时平滑回缩，顶部操作栏和窗口上沿保持不动；动画期间渲染表面逐帧跟随窗口尺寸，避免内容被拉伸。静态与动态模糊下，展开动画中的玻璃区域会随动画实时延展。
- 应用图标为扁平的扫描框图形，设置使用经典齿轮图标，整体遵循 Windows 11 Fluent 的圆角、留白与配色。
- 三档模糊均持久化；旧版本的「半透明玻璃效果」开关会自动迁移到静态模糊。

### 资源占用

- **静态模糊**：玻璃背景在窗口显示、从托盘恢复、扫描结束和按住开始拖动时采样，并复用低分辨率模糊纹理；拖动过程中只按新位置取用该纹理，不持续抓屏，也没有轮询计时器。拖动开始时的重采样放在工作线程里完成（拖动不会因此卡顿），期间通过 `WDA_EXCLUDEFROMCAPTURE` 把窗口从截屏中排除（窗口本身保持可见，不会闪烁），因此取到的是窗口背后的当前桌面，而不是上次残留的旧背景。
- **动态模糊**：每约 40 ms 在**工作线程**上抓取整块虚拟桌面（不带 `CAPTUREBLT`，避免指针闪烁），缩小约 1/12 后模糊成一张覆盖全桌面的纹理；拖动期间不抓屏，只按窗口新位置重新映射这张纹理，所以跟手无延迟。采样通过 `WDA_EXCLUDEFROMCAPTURE` 排除窗口自身，不需要隐藏或闪烁。
- **无模糊**：不进行任何背景采样或模糊绘制，适合老设备。
- 三档模糊共用同一个 Direct2D 窗口渲染目标，不创建额外的 Direct3D / DXGI / DirectComposition 设备。
- 界面只在交互、主题变化或窗口重绘时刷新；静态模式在展开动画期间复用已生成的纹理。
- 隐藏到托盘、最小化或退出时会停止实时采样计时器并恢复窗口在截屏中的可见性；窗口隐藏时释放 Direct2D 渲染目标，重新显示时按需创建。
- GitHub 更新检查只在点击按钮时联网，不在后台轮询。

### 托盘常驻与开机自启

- 「关闭窗口时最小化到托盘」：开启后点击 × / Alt+F4 会隐藏主界面并在系统托盘继续运行；关闭选项后点击 × 直接退出。设置会保存。
- 单击托盘图标即可打开主界面；右键打开托盘菜单：全屏识别、框选识别、设置、后台常驻/自启动开关、退出。
- 「开机自启动（仅托盘）」：写入当前用户的 Windows 启动项（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）。登录 Windows 后程序直接在托盘启动，不展示主界面，并自动注册全局快捷键。
- 单实例：程序已在托盘时再次启动会唤起现有窗口，不会重复创建托盘图标。
- 托盘图标与窗口、任务栏、开始菜单、桌面快捷方式是同一套扫描框图形（同一几何、同一比例），只把托盘用的那份整体等比放大到铺满通知区域格子，避免在系统托盘里看起来比别的图标小一圈。
- 从托盘/快捷键发起的扫描结束后会返回托盘，不会打断当前工作。

### GitHub 自动更新

- 设置 → 关于与更新 → 「检查更新」，通过 GitHub Releases 获取最新正式版本；只有用户点击时才访问网络。
- 发现新版本后，按钮会变为「更新到 vX.Y.Z」；点击后自动下载对应资产并用 Release 中的 `SHA256SUMS.txt` 校验。
- **安装版**：通过一次 UAC 启动下载的安装程序（`/S /EASYQRUPDATE`）。安装程序会通知并等待 EasyQR 完全退出后再覆盖文件，完成后自动以普通权限重新启动新版本；新版本启动时读取一次性更新标记，在设置页显示「已更新到 vX.Y.Z」，无需再次点击检查更新。保留原安装目录与桌面快捷方式选择。
- **便携版**：校验通过后原地替换 `EasyQR.exe` 并重启，旧文件在下次启动时清理；不需要安装或管理员权限，重启后同样会显示更新完成状态。
- 更新失败、网络不可用或尚无正式 Release 时会在设置页给出提示，不影响扫码功能；若更新中途失败，下次启动会提示「上次更新未完成」。
- 发布新版本时推送 `v*` tag，GitHub Actions 会自动构建并发布包含 `EasyQR.exe`、便携 zip、安装包和 `SHA256SUMS.txt` 的 Release。

### 全局快捷键

- 默认：
  - **Win + Shift + Q**：全屏识别
  - **Win + Shift + W**：框选识别
- 在设置 → 快捷键中可以点击按钮后直接按下新的组合键；选择立即生效并持久化。
- 快捷键需包含 Ctrl / Alt / Shift / Win 之一，或使用 F1–F24；如果被其他程序占用会提示并恢复原快捷键。
- 程序运行期间快捷键全局可用，主窗口隐藏到托盘时同样有效。

### 全屏识别

- 主窗口隐藏后捕获整个虚拟桌面（包含所有显示器）。
- 识别到 **1 个可打开网页的码**：不显示加灰选择层，直接在码的中心显示高亮按钮标记，约 0.5 秒后用默认浏览器打开。
- 识别到 **1 个非网页的码**：直接显示识别结果面板。
- 识别到 **多个码**：全屏加灰，在每个码中心显示 Acrylic 玻璃按钮；网页按钮直接打开浏览器，非网页按钮打开对应结果面板。
- 未识别到任何可读内容时显示提示。

### 框选识别

- 主窗口隐藏，全屏加灰并显示十字准星；拖动框选，界面与操作接近 Windows 11「截图工具」。
- 松开后只识别选区内的码；单码按“网页直接打开 / 其他显示结果面板”处理，多码进入选择层，未命中时显示提示。
- `Esc` 或右键取消，回到发起扫描的位置（主界面或托盘）。

### 识别结果面板

- 显示识别到的码制（如 QR Code、Code 128、Data Matrix 等）和完整文本内容。结果面板、识别按钮与无结果提示统一使用基于当前屏幕的 Acrylic 玻璃层（模糊 + 着色），与主窗口材质一致。
- 点击「复制内容」可把完整内容放入 Windows 剪贴板；复制只在用户主动点击时发生。
- 只有内容为 `http://` / `https://` 网页时才会交给默认浏览器；其他内容不会被自动搜索或上传。

### 支持的码制

ZXing-C++ 提供的标准读取器已全部启用，常见包括：

- 二维码：QR Code、Micro QR、rMQR；
- 二维条码：Data Matrix、Aztec、PDF417、MaxiCode；
- 一维码：Code 39、Code 93、Code 128、ITF、Codabar、EAN-8、EAN-13、UPC-A、UPC-E、GS1 DataBar / DataBar Expanded；
- 带 Logo、圆点、彩色等变体的标准二维码同样可识别。

**封闭格式无法离线支持**：抖音圆形扫码、微信小程序码、厂商专有的“三维码”等没有公开解码规范，只有对应平台官方 App/SDK 能解。这不是换一个通用解码库能解决的问题。

## 隐私

- 扫描截图、灰度图、主窗口玻璃采样和识别结果全部保留在**内存**中，不写入任何临时图片文件；选择无模糊时不会生成主窗口玻璃采样。
- 动态与静态模糊的玻璃采样通过 `WDA_EXCLUDEFROMCAPTURE` 把 EasyQR 自身排除在截屏之外，因此在这两档（尤其是动态档实时采样期间）用系统截图工具或录屏软件抓取桌面时，EasyQR 窗口不会出现在结果里；窗口在屏幕上始终正常可见，切到无模糊或退出后会立即恢复。
- 不保存扫描历史、图像或识别结果，不做任何遥测。
- 除用户主动点击「检查更新」外，应用不发起网络请求；更新检查通过 GitHub API 获取版本，并从 GitHub Releases 下载更新文件和 SHA-256 清单。下载的临时文件位于 `%TEMP%\EasyQR`，验证完成后删除，残留会在下次启动时清理。
- 只有在用户触发结果时，才通过系统 `ShellExecute` 交给默认浏览器打开目标网页；只有点击「复制内容」时才写入剪贴板。
- 会持久化的内容只有偏好设置：
  - `HKCU\Software\EasyQR\ThemeMode`（主题）
  - `HKCU\Software\EasyQR\CloseToTray`（关闭窗口时驻留托盘）
  - `HKCU\Software\EasyQR\GlassMode`（无模糊 / 静态模糊 / 动态模糊；旧的 `Translucency` 值会在首次启动时迁移）
  - `HKCU\Software\EasyQR\HotkeyFullscreen` / `HotkeyRegion`（快捷键）
  - 开启开机自启动时，在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写入一个 `EasyQR` 启动项
- 更新过程中会临时写入 `HKCU\Software\EasyQR\PendingUpdateVersion`，用于安装完成后确认版本并自动恢复界面；读取后立即删除，不属于长期偏好。
- 不保存任何图像、识别文本或扫描记录。安装版卸载时会删除上述设置和自启动项。

## 系统要求

- Windows 11 x64（推荐）；动态模糊在常驻工作线程上连续采样窗口周围区域并模糊（目标 8 ms/帧，实际帧率取决于机器），静态与无模糊不做持续采样；实时透明档需要 Windows 11 24H2（Build 26100）及以上。
- Windows 10 x64 亦可运行，三档行为一致（动态模糊同样是程序侧实时采样）。Windows 10 下系统圆角会缺失。
- 自动更新安装版需要联网并在启动安装程序时确认一次 UAC；便携版自动更新不需要管理员权限。
- 不依赖 .NET、WinUI 运行时、WebView2 或 VC++ Redistributable。

## 下载与安装

构建产物位于 `dist/`：

| 文件 | 说明 |
| --- | --- |
| `EasyQR.exe` | 便携版单文件，双击即用 |
| `EasyQR-1.4.18-x64-portable.zip` | 便携版压缩包（含 EXE 与 LICENSE） |
| `EasyQR-1.4.18-x64-setup.exe` | 安装版 |
| `SHA256SUMS.txt` | 上述文件的 SHA-256 校验和 |

### 安装版

- 安装向导支持选择安装目录；开始菜单快捷方式固定创建，桌面快捷方式可选。
- 在 Windows「设置 → 应用 → 已安装的应用」中可正常卸载。
- 卸载会删除程序文件、开始菜单 / 桌面快捷方式、卸载注册表项、`HKCU\Software\EasyQR` 下的偏好以及开机自启动项。
- 安装包使用标准 NSIS 引导程序（32 位 stub），安装的 `EasyQR.exe` 为纯 64 位。
- 二进制未做代码签名，首次运行时 SmartScreen 可能提示；可核对 `SHA256SUMS.txt` 后选择「更多信息 → 仍要运行」。

### 便携版

把 `EasyQR.exe`（或解压 portable zip）放到任意目录，双击运行即可。不会安装服务或留下临时文件；会按需写入上面列出的偏好和自启动项。不再使用时，关闭开机自启动并删除 `HKCU\Software\EasyQR` 即可。

## 使用提示

- 全屏识别会涵盖所有显示器，按钮直接叠加在各码中心。
- 只有一个可打开网页的码会自动跳转；多个结果时出现可取消的选择层。
- 非网页内容（多数一维码、普通文本等）会进入结果面板；如果一维码中编码的也是 `http/https` 网页，同样会直接打开。
- 深色 / 浅色 / 跟随系统只影响主界面；全屏扫描遮罩为保证可读性始终使用深色。
- 部分受 DRM 保护的窗口、独占全屏 HDR 游戏画面可能无法被 GDI 正确截取。
- 多个二维码指向同一域名时，按钮上的域名标签会相同，请按位置选择。
- 如果任务栏仍显示旧版图标，通常是 Windows 图标缓存或旧的固定快捷方式导致：取消固定 EasyQR 后重新固定，或重启资源管理器即可；程序启动时已主动通知 Shell 刷新图标。

## 构建

### Linux（仓库使用的交叉编译方式）

依赖：`cmake`、`mingw-w64`（x86_64）、`nsis`、`zip`。ZXing-C++ 与 quirc 源码均已内置在 `vendor/`，无需联网拉取。

```bash
sudo apt install cmake g++-mingw-w64-x86-64 nsis zip
./tests/run_tests.sh     # 原生 URL / 码制解码回归测试
./scripts/build.sh       # 按 src/version.h 生成便携版与安装版
```

### 发布新版本

自动更新依赖 GitHub Release 资产。推送版本 tag 即可由 Actions 自动构建并发布：

```bash
git tag v1.4.18
git push origin v1.4.18
```

发布内容必须包含 `EasyQR.exe`、`EasyQR-<版本>-x64-portable.zip`、`EasyQR-<版本>-x64-setup.exe` 和 `SHA256SUMS.txt`；仓库内的 `build.yml` `release` job 已按此约定自动上传。

### Windows（MSYS2 MinGW-w64）

需要 CMake、MinGW-w64 GCC 与 NSIS。可直接用 CMake 构建（不加载 Linux 的 toolchain 文件），再通过 `-DAPP_EXE=... -DOUTPUT=... -DAPP_ICON=... -DLICENSE_FILE=...` 调用 `makensis`。仓库的 GitHub Actions 也提供了 Linux 交叉构建流程。

## 项目结构


## 更新记录

### 1.4.18

- 修复动态模糊收进托盘后桌面上残留的圆角框（1.4.15 的重绘桌面无效）：那条 1px 圆角边框其实是 **DWM 自己画的窗口边框**，不是我们的像素——它不受 `WDA_EXCLUDEFROMCAPTURE` 约束，所以既会出现在截图里，也会在窗口隐藏后留在桌面层。现在用 `DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE` 让 DWM 完全不画这条边框（圆角遮罩仍然生效，界面外观不变）。
- 采样帧改为「只保留最新一帧」：工作线程每帧只把最新结果放进槽位并唤醒 UI 一次，UI 忙的时候**直接丢弃被超越的旧帧**，不再排进消息队列。此前 UI 跟不上时每一帧都会被延迟应用，等于把排队时长加进了延迟。
- 探针的诊断行补上更细的四个数：`实测 N/s`（UI 实际应用的帧率）、`抓 Nms`（抓屏+缩小耗时）、`循 Nms`（整个采样循环的节拍）、`总 N`（累计投递帧数）。用 `--probe=10` 启动即可看到，用来区分「抓屏慢」和「UI 处理慢」。

### 1.4.17

- 修复「检查更新」可能把用户带回旧版本：更新检查此前读取 GitHub 的 `releases/latest`，而它的「latest」按**发布时间**排序——1.4.15 的 CI 排队卡了约 50 分钟，恢复后比 1.4.16 还晚发布，于是 `latest` 指向了 1.4.15。现在改为拉取发布列表并自己按版本号取最高（跳过 draft / prerelease），发布顺序再乱也不会误报。

### 1.4.16

- 动态模糊的帧率问题定位到根因：真机实测只有约 **10 fps**（每帧 ~100 ms），而 1.4.12 为了省内存把缩小挪进了 `StretchBlt`+`HALFTONE`——GDI 的高质量重采样要逐源像素处理，比「直接 BitBlt + CPU 粗略下采样」慢一个数量级。现在撤回这条优化，抓屏恢复纯 `BitBlt`，缩小放回 CPU 侧。
- 抓取区域从「整块虚拟桌面」改为「窗口 + 128 px 余量」：抓屏耗时是帧率的唯一瓶颈，而玻璃只需要窗口周围那一块。以 2560×1440 桌面、400×240 窗口计，单次抓取面积降到约 1/10。余量按「两帧之间窗口能移动多远」来定（快速甩动约 80 px/帧），超出已采样区域时源矩形是平移夹取，所以只会短暂粘滞，**不会黑屏也不会变形**，且采样区域每帧重新以窗口为中心。
- 采样器改为**常驻工作线程自转**：不再用 `SetTimer` 唤醒 + 每帧新建线程，唤醒开销和线程创建本身都吃掉了帧率；线程内用 `timeBeginPeriod(1)` + 性能计数器按 8 ms 目标节奏（对应 120 Hz 屏）自限速，只有缩小模糊后的小纹理跨线程回传，全分辨率缓冲不再反复分配。全黑帧的丢弃判定也移到了工作线程。
- 探针第 10、11 档的目标节奏降到 6 ms，用来对照「再快一点是否还有意义」；设置页那行的 `实测 N/s` 就是唯一的判据。诊断文案里写死的「约 50fps」删掉了——请求多少和实际多少是两回事。

### 1.4.15

- 继续修动态模糊下收进托盘后桌面残留的圆角框：1.4.14 调整了还原截屏排除属性的时机，但真机上仍然残留，说明问题不在时机，而是**桌面那一层没有被重绘**——窗口带着 `WDA_EXCLUDEFROMCAPTURE` 消失后，它原来覆盖的区域保留了排除生效时的合成结果，所以残影只在桌面上、会被上层窗口盖住。现在窗口隐藏或退出后调用 `SystemParametersInfo(SPI_UPDATEDESKWALLPAPER)`，让外壳重画桌面。

### 1.4.14

- 新增第四档模糊设置：**实时透明**。它不采样也不模糊，而是让窗口表面带上真正的逐像素 Alpha（`DWMWA_REDIRECTIONBITMAP_ALPHA`），桌面在 DWM 合成期直接透过来——和 Windows 终端的透明度完全同源，因此拖动、背景视频都不存在任何延迟。低于 Windows 11 24H2（Build 26100）时该属性会被拒绝，此时这一档自动表现为无模糊，并在设置页注明。
- 探针补到 11 档（`F1`–`F11` 切换）并修正诊断语义：`材质` / `边框` 现在区分「拒绝」与「未试」，不会因为某个档位压根不调用就被误读成失败。新增第 8、9 档验证一个假设——系统材质是画在「窗口及其非客户区」后面的，而我们摘掉了 `WS_THICKFRAME`、自己应答 `WM_NCACTIVATE`，DWM 可能因此判定这窗口没有需要画材质的框架；这两档恢复标准带框窗口的样式约定（`WM_NCCALCSIZE` 仍返回 0，界面尺寸不变）后再试 Acrylic / Mica。
- 针对第 5 档「历史背景 + 实时背景双重叠加」的问题新增第 10、11 档：抓屏间隔从 20 ms 降到 10 ms，第 10 档把采样纹理画成完全不透明（彻底消掉双重曝光），第 11 档保留 0.92 的轻微混合。诊断行会同时显示**实测采样帧率**，因为请求 10 ms 不等于能跑到 10 ms（同一台机器上 Wine 里只能跑到约 51/s）。
- 实时透明档不做任何持续采样，也不在拖动开始时重采样，功耗与无模糊一致。
- 修复动态模糊下把窗口收进托盘后，桌面上留下一个圆角透明框：隐藏前会先还原 `WDA_EXCLUDEFROMCAPTURE`，等于在窗口还在屏幕上的瞬间让 DWM 重建它的合成层；现在改为先隐藏窗口再还原截屏排除属性，并且晚到的抓屏结果不再应用到已隐藏的窗口上。

### 1.4.13

- 新增一个默认关闭的**系统材质探针**，用来在真机上确认 Windows 11 24H2 的逐像素透明路线能拿到什么效果。`DWMWA_REDIRECTIONBITMAP_ALPHA`（属性 39，Build 26100 起）让 DWM 尊重普通窗口表面的 alpha——在此之前官方文档明确写着该表面「按完全不透明处理」，这正是 1.4.7 未绘制区域显示为黑色的原因。表面一旦带上 alpha，DWM 画在表面**后面**的系统材质就有机会透出来，而材质是合成期采样的，结构上不可能滞后。
- 探针用命令行开启：`EasyQR.exe --probe=N`（N 取 1–7），运行中按 `F1`–`F7` 直接换档、`F12` 回到正式版渲染路径，不需要重启。设置页「模糊」下方会显示当前档位、系统构建号，以及 `alpha` / `材质` / `边框扩展` 三个 DWM 调用是否被接受。
- 七个档位分别是：1 = 只有 alpha（终端式纯透明 + 我们自己的色调，无模糊）；2 = alpha + 系统 Acrylic + `DwmExtendFrameIntoClientArea`；3 = alpha + 系统 Acrylic（不扩展边框）；4 = alpha + 系统 Mica + 扩展边框；5 = alpha + 把程序侧采样模糊画成半透明（比现在更通透，但仍是采样）；6 = 只透出系统 Acrylic，完全不叠我们自己的色调（用来判断材质本身到底画没画）；7 = alpha + `DWMSBT_TABBEDWINDOW` 材质 + 扩展边框。
- 探针只在渲染目标上启用预乘 Alpha；属性 39 不被接受时（24H2 之前）自动按原来的不透明路径绘制，诊断行会显示 `alpha=失败`，行为与 1.4.12 完全一致。

### 1.4.12

- 动态模糊在拖动窗口时背景不再冻结在拖动开始的那一帧：1.4.11 为了消除卡顿，在拖动期间完全暂停了采样，代价是背景视频在拖动过程中停止更新。现在采样贯穿整个拖动过程，单张抓屏仍然只在工作线程上进行、同一时刻只有一帧在途。

- 静态模糊的拖动起始采样同样走这条缩小路径，拖动开始的准备时间也随之变短。

### 1.4.11
